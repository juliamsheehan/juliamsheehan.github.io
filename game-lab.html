🎮 The Game Lab

A hands-on lab where you plan, build, code, test, and share your own little maze game — the Digital Game Design activity. It's been built two different ways, and both still run. Play them back-to-back to see how the project grew from version 1 to version 2.

Two versions, one activity

Same goal both times — help a beginner design and code a small game — but rebuilt from the ground up with a different engine and a different way of coding the game's rules.

🦊
Version 1 · the original

Game Design Lab

Built on the Phaser game engine, guided by Pip the fox. You paint a world, code its brain with drag-and-drop blocks, then play it with the arrow keys and print a certificate.

Tech: Phaser + several JS modules (game, coder, share, themes).

Version 2 · newest 🆕

Coding for Good — Digital Game Design

A ground-up rebuild in plain HTML/CSS/JS — no game engine. The rules are coded with a Scratch-style event editor (event "hat" blocks with nested actions), and finished games are shared as a self-contained link, no server needed.

Tech: hand-written grid engine + block interpreter; ~0 dependencies.

What changed between v1 and v2 — and why

Rebuilding it wasn't just a fresh coat of paint. Each change was a deliberate design choice:

🧩

From a game engine to zero dependencies

v1 leaned on Phaser (a ~1 MB library). v2 is a small, hand-written grid + interpreter, so it loads instantly and is easy to read, host, and maintain.

🎛️

From block programs to event scripts

v2 codes rules like Scratch: when ▲ pressed → move up, when I touch a key → open the door. Kids program the behavior itself, not just a fixed program.

🔗

Shareable, self-contained games

v2 encodes your whole maze and its code into a single #play=… link — a friend opens it and plays instantly, no download and no server.

📱

Rethought layout & play

The maze and code blocks sit side-by-side like a real editor, with an on-screen D-pad for tablets and a "turn sideways" prompt on small phones.
